# Text-first blog content

Put posts and attachments in the `entries/` submodule, which tracks `master` in [`libredove/content`](https://github.com/libredove/content). Its directory tree is the URL tree:

```text
entries/
  notes/hello.txt       -> /notes/hello.txt
  images/photo.jpg      -> /images/photo.jpg
  papers/report.pdf     -> /papers/report.pdf
```

Requests for `/` and nested directories return a dynamically formatted directory listing. Browsers that request HTML receive clickable names; clients requesting plain text receive an `ls -lahF`-style `text/plain` listing. The HTML is generated by the Worker at request time; there are no HTML files. Files are served directly with their asset content type, so plain text, images, and PDFs work without a page template.

The Worker runtime cannot enumerate its static asset bundle. `npm run build` therefore uses Node's filesystem API to create a small path/size/modified-time index from `entries/`; timestamps are rendered in UTC as `YYYY-MM-DD HH:mm:ss`. The Worker uses that index to render listings at request time. The build skips Git metadata and the submodule's `.github` directory so repository machinery is not published. `npm run dev` and `npm run deploy` build the index before starting Wrangler.

## Editing and publishing

On a Mac, clone with `git clone --recurse-submodules` or initialize the submodule with `git submodule update --init --recursive`. Add, move, or delete files inside `entries/`, then commit and push in that repository. From iPhone or iPad, use a Git client that supports submodules to edit text files, add attachments from Files, commit, and push.

Each push to the content repo's `master` branch signals this repo's deploy workflow. For that cross-repository trigger, add a fine-grained token as the content repo's `BLOG_REPO_DISPATCH_TOKEN` secret, scoped to `libredove/cfbs` with `Contents: write`. The blog repo workflow updates the submodule pointer to the pushed commit and deploys it. The blog repo also needs its existing `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` secrets. You can deploy manually with `npm run deploy` from a Mac with Wrangler configured. No upload endpoint is included.

Empty directories are not represented by Git. Add a file to a directory for it to appear; the placeholder `entries/.gitkeep` is omitted from listings.
